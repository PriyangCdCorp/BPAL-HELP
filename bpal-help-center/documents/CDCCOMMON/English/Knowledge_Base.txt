# BPAL AI Assistant Knowledge Base

**Edition:** 1.0 — working training edition  
**Prepared:** 21 October 2026  
**Purpose:** Authoritative functional grounding for an AI assistant that teaches BPAL end users and answers operational questions.  
**Scope:** Shared master-data folder functionality, common notebook controls, Mini Containers, Messages, Notes, Audit, and known exceptions. Detailed Transaction workflows and individual notebook field rules remain out of scope.

> **Status convention:** Unless explicitly labeled **Pending verification** or **Proposed enhancement**, the functionality below was described by a CDCorp BPAL subject-matter expert during a detailed walkthrough. Examples are illustrations, not additional verified functionality.

## 1. Instructions for the BPAL AI Assistant

### 1.1 Mission and response method

Explain how existing BPAL functionality behaves and guide users through the actual interface. Prefer concrete steps using BPAL's names for buttons, menus, tabs and fields. If the question is ambiguous, ask which folder and whether the user has update or read-only authority. For folder operations, distinguish the main folder, a Mini Container inside a notebook, and the record notebook itself. Explain the effect on the database versus the already-loaded folder container.

Do not invent unavailable features, database rules, field definitions, access permissions, validation, automatic synchronization, or special Transaction behaviour. If a required detail is not documented, state that it has not yet been confirmed and recommend checking with a BPAL administrator or CDCorp support. Never describe a proposed enhancement as a feature that exists today.

When answering a question, lead with the action the user should take, then briefly explain the expected result and important caveats. For errors, explain the probable cause only if documented, and separate it from other possibilities. Do not tell users to bypass permissions, record locks, or database referential integrity.

### 1.2 Confidence labels for assistant implementation

- **Confirmed**: A described BPAL behaviour supported by the walkthrough.
- **Pending verification**: A known question whose exact behaviour has not been established. Do not assert an answer.
- **Proposed enhancement**: A possible software change; not an implemented feature.
- **Illustrative example**: Demonstrates a confirmed rule with sample values; not a production-specific guarantee.

### 1.3 Intent and terminology routing

- **Folder**: Main container of retrieved rows, with standard toolbar and configurable presentation.
- **Notebook**: Detailed screen to create, view or update one record; may contain several tabs and Mini Containers.
- **Mini Container**: Folder-like grid embedded in a notebook and tied to its current parent record.
- **Selection Criteria / Select**: Database retrieval conditions; not just a search within currently displayed rows.
- **Find**: Single-record lookup using primary-key information; not a search through the existing grid.
- **Open**: Opens highlighted folder record(s); update access requires CDC Manager lock.
- **Auto Ref**: Toggle controlling the automatic initial retrieval when opening a folder; not a timer-based periodic refresh.
- **Refresh / Stop**: SQL COUNT followed by fetch into the folder; Stop interrupts fetching, retaining rows already loaded.
- **Columns / Sort**: Local presentation functions; no additional SQL retrieval simply to change columns or sort loaded data.
- **Profile**: Saved named references to saved Selection, Column and Sort configurations.
- **Apply**: Saves notebook edits to the database but keeps the notebook open.
- **Messages**: Effective-date, destination and language-dependent messages linked to BPAL records.
- **Notes**: Record-linked text and optional references to external files; one note can be designated as the Folder Note.
- **Audit**: History of database changes, with old/new values for changed fields.

## 2. What BPAL Is and How Its Records Are Organized

BPAL's central purpose is collecting and managing operational transactions. Vendor, Client, Product, Contract and similar folders primarily provide master data to support those transactions. Master-data folders may contain thousands of rows, while Transaction tables may contain millions. The Transaction folder includes special retrieval restrictions and a more elaborate Selection Criteria dialog; do not generalize standard-folder instructions to it without checking the dedicated documentation.

BPAL's graphical folder is a **container**. SQL via ODBC retrieves full rows of all available columns into the container. BPAL supports DB2 and Microsoft SQL Server through ODBC. User selection criteria are part of the database query. Once records are in the container, users can change column visibility and sorting locally. Notebook opening usually fetches the record afresh from the database rather than using the folder's stored row as the notebook's authoritative current state.

Users' saved selections, sorts, column layouts, Profiles, Auto Ref preferences, and remembered split-bar locations are associated with individual folders where documented. A folder's initial authority (read-only or update) determines which operations are available.

## 3. Standard Folder: Opening, Auto Ref, Refresh and Stop

### 3.1 Auto Ref

**Auto Ref is a persistent on/off toggle for initial retrieval.** When enabled, opening a folder automatically runs the applicable default Selection Criteria and retrieves data. When disabled, the folder opens initially empty until the user explicitly invokes Refresh or applies Selection Criteria/Profile. Auto Ref is not periodic refresh. Its setting is maintained per user and per folder, including Mini Containers.

If a default Profile exists, its referenced Selection Criteria takes precedence over an individual saved default selection. If a selected Profile leaves a component unspecified, the currently active setting for that component remains in effect.

### 3.2 Manual Refresh lifecycle

1. BPAL clears every currently displayed row from the container.
2. It executes an SQL `COUNT` using the active Selection Criteria to establish the number of matching records. During this phase the status bar displays **One moment please**.
3. BPAL executes its SQL data-fetch operation and progressively adds matching records to the folder.
4. During retrieval, the Refresh button becomes **Stop**, and the status bar reports loaded rows, total from COUNT, percentage and elapsed time, for example `234 of 1586 (14%) (1.487 seconds)`.
5. After fetching ends, either normally or following Stop, BPAL applies the configured container sort to the rows loaded. The toolbar button returns to Refresh.

The displayed elapsed time covers the overall refresh operation, including COUNT. The current final status, for example `206 rows displayed (1.461 seconds)`, does not identify whether retrieval finished normally or was interrupted.

### 3.3 Stop and partial results

Pressing **Stop** while records are being fetched halts further retrieval, but **does not restore the old rows** and **does not remove newly fetched rows**. The partially loaded results remain displayed and are sorted when fetching terminates. Stop may also take effect in the interval after COUNT and before fetch starts. The initial SQL COUNT itself currently cannot be cancelled by the Stop button; users may have to wait for it to finish.

**Important:** An interrupted folder may display only some of the records matching the active Selection Criteria. A status of `0 rows displayed` alone does not prove that there are zero database matches.

### 3.4 Answer example

**Q: My folder is empty when I open it. Is it broken?**  
**A:** Check whether **Auto Ref** is enabled. When Auto Ref is off, a folder opens without fetching records. Click **Refresh** to retrieve records using the active Selection Criteria, or use **Select** to choose a different selection. If the folder still shows zero rows, check the criteria before concluding that no matching records exist.

**Q: I pressed Stop and now my folder shows fewer rows.**  
**A:** Stop halts the fetch and leaves the records retrieved up to that moment. The prior rows were cleared at the start of Refresh. Click **Refresh** again to rerun a complete retrieval, or narrow your Selection Criteria if the folder is large.

## 4. Database Selection Criteria (Select)

### 4.1 Purpose, limits and operators

Click **Select** to configure which records BPAL retrieves from the database. Standard folders allow **up to 10 conditions**, one per row. Each condition has **Column**, **Operator**, and **Value**. The Column dropdown contains every column defined for that folder; the column-name list may be in CDCorp-configured logical order or user-selected alphanumeric order. Filled condition rows are joined with logical **AND**.

The common Operator list includes: `=`, `<>`, `<`, `>`, `<=`, `>=`, `STARTING WITH`, `NOT STARTING WITH`, `CONTAINING`, `NOT CONTAINING`, `RANGE`, `IS NULL`, and `IS NOT NULL`. The same list is presented for all column types; BPAL rejects incompatible combinations, for example `STARTING WITH` on a numeric Material Id, displaying **The selected operator does not apply to numeric values!** Blank operator entries correspond to rows without a chosen column.

For `=`, comma-separated values represent alternatives for the same condition, such as `Status = A, I`. The **RANGE** operator expects exactly two comma-separated endpoints and includes both boundaries. Example: `Material Id RANGE 1000, 2000` includes 1000 and 2000. With separate conditions `Status = A` and `Product Description CONTAINING OVER`, a record must satisfy **both**.

### 4.2 Values and lookups

Users can type values manually into the Value field, including multiple comma-separated codes. If BPAL recognizes a flag-value list or an associated lookup table, the magnifying-glass icon activates to offer selectable values. Example: Status presents `A - Active` and `I - Inactive` with checkboxes. Selecting both yields a comma-separated value such as `A, I`. Lookups are optional for users who know the codes.

For date fields, the lookup control becomes a **calendar icon**, which opens the BPAL Calendar dialog.

### 4.3 Date selection and dynamic expressions

The Calendar shows three months and supports month/year navigation. Its Date type choices are **Specific**, **Today**, and Sunday through Saturday. **Specific** returns a fixed date formatted `YYYY-MM-DD`. **Today** with a Days offset returns a dynamic expression such as `TODAY-7`, evaluated as seven calendar days before the current day when the selection is used.

When a weekday is selected, **Days** becomes **Weeks**. BPAL defines each week as **Sunday through Saturday**. Blank or zero selects that weekday in the current calendar week, even if the day is still in the future; `-1` selects that weekday in the previous calendar week. For Monday 19 October 2026, `SUNDAY` = 18 October, `SATURDAY` = 24 October, `SUNDAY-1` = 11 October and `SATURDAY-1` = 17 October. BPAL returns the expression rather than the calculated date, making it reusable in saved selections.

Relative expressions can be used with **RANGE**. Example: `SUNDAY-1, SATURDAY-1` specifies the entire previous Sunday-to-Saturday week, inclusive.

### 4.4 Named selections, defaults and buttons

- **User id**: Switch to another user's named saved Selection Criteria for that folder. This helps two users obtain comparable results. Saving a change stores it under the **current** user's ID rather than overwriting the other user's copy.
- **Save As**: Choose an existing saved selection or name a new one.
- **Default**: Only one saved selection per user per folder may be default; choose the saved selection, check Default and press Save to replace the previous default.
- **Save**: Persist a named selection; not required to test a change.
- **OK**: Apply the conditions currently shown and **immediately Refresh** the folder, whether saved or not.
- **Cancel**: Close the dialog without applying or saving unsaved edits; leave the folder unchanged.
- **Reset all**: Clear all ten conditions. Following Reset all with OK retrieves **all records** in a standard folder.
- **Delete**: Remove the chosen named saved selection for that folder.

Users may save an entirely empty selection, such as `All`, and even make it their default. With Auto Ref enabled, that can cause all folder rows to be retrieved on opening, so users should consider folder volume.

### 4.5 Answer examples

**Q: How do I display only active products whose descriptions include OVER?**  
**A:** Open Product → **Select**. On the first row select Column **Status**, Operator `=`, Value `A`. On the second select **Product Description**, Operator **CONTAINING**, Value `OVER`. Click **OK**. BPAL uses AND across the two rows and refreshes the folder. Click **Save** first only if you want to keep these conditions under a name.

**Q: How do I make a selection for the previous full week?**  
**A:** On a date column choose **RANGE** and enter `SUNDAY-1, SATURDAY-1`. BPAL evaluates those expressions using Sunday-to-Saturday calendar weeks. You can save the selection for repeated use. Be aware that Transaction has additional restrictions and date/period controls.

**Q: I clicked Reset all and now thousands of rows are loading. Why?**  
**A:** In standard Selection Criteria, Reset all removes every retrieval condition. Clicking OK then retrieves all database rows for that folder. Press Stop to halt fetch if appropriate; an initial COUNT may still take time to finish.

## 5. Column Selection (Columns)

The **Columns** dialog has **List All** on the left (all available folder columns) and **Select All** on the right (the displayed columns, in their chosen left-to-right order). Select a column and **Add (`>>`)** or **Remove (`<<`)** it; use **Move Up** and **Move Down** to change display order. The user can select several columns on the left to add all of them. Changing visible columns does **not** query the database: BPAL already fetched all defined columns into the container.

**OK** applies changes immediately without saving them. Named layouts, User id, Save As, Default, Save and Delete work like those for Selection Criteria, including using another user's saved layout and saving a personal copy. **Reset all** clears the right-side list; unlike Selection Criteria, an empty selected-column list is invalid and clicking OK displays an error requiring **at least one column**.

Available-column dropdown/list ordering can use the CDCorp-defined logical order or alphanumeric order. A global setting establishes a preference; an individual folder's **Options** menu can override it. This is ordering of **available column names in selection interfaces**, not the displayed folder's data rows.

**Q: Can I show a hidden column without refreshing?**  
**A:** Yes. Click **Columns**, move the desired column from the left list to the right, adjust its position and click **OK**. BPAL displays it from the data already loaded.

## 6. Folder Sort Criteria (Sort)

The **Sort** dialog lists available columns on the left and chosen sort keys, in priority order, on the right. Choose **Ascending** or **Descending** to add a key, **Toggle Sort** to reverse an existing key, **Remove** to remove one, and **Move Up/Down** to change priority. Example: **Category [ASC]**, then **Product Code [ASC]** sorts first by Category and within category by Product Code.

BPAL intentionally does **not** send an `ORDER BY` for folder fetches. Sorting is performed by the local folder container **after record fetching finishes**, whether the fetch completed normally or was interrupted via Stop. Changing Sort later reorders rows already in the folder without another SQL query.

Sort has the same named configurations, User id, Default, Save, Delete, OK and Cancel principles as Selection Criteria and Columns. **Reset all followed by OK** applies no explicit sort. Without a sort configuration, users should not assume the database's natural retrieval order is stable.

**Q: Why are the rows sorted even though I pressed Stop?**  
**A:** BPAL sorts the rows that were successfully fetched after retrieval ends, including when the user interrupts the fetch. The folder may be incomplete but the rows that are present are sorted.

## 7. Folder Profiles

A **Profile** is a named set of **references** to individually saved **Column**, **Sort**, and **Selection** configurations. It is not a copy of the individual settings. Each of the three components is optional. A Profile can specify only Selection Criteria, for example, while leaving the current columns and sort unchanged.

In the **Folder Profile** dialog, the three fields let the user pick saved configuration names. **Use Current** fills a field with the name of the saved configuration presently active for that function. Save As gives the Profile its own name; Default designates the default Profile. A default Profile **takes priority** over individually saved default Columns, Sort and Selection Criteria when opening that folder.

Click **OK** on a Profile to apply all the referenced configurations and initiate a Refresh. Where a Profile component is blank, BPAL retains the currently active configuration for that function.

**References remain live**: if Profile `Review` uses saved Sort `Description`, and that Sort is later edited from description-only to description-then-code, Profile `Review` uses the revised saved Sort. If the referenced Sort is deleted, BPAL applies no sort from that reference. The exact response to a deleted referenced Column or Selection configuration is **pending verification**; do not claim that BPAL definitely retrieves all rows or that it definitely displays an error.

**Q: Why did my Profile change without anyone editing the Profile?**  
**A:** A Profile points to named saved configurations. If one of those configurations is edited, the Profile picks up the new definition automatically. Check the referenced Selection, Sort and Column names.

## 8. Find: Direct Record Lookup

**Find** uses a primary key to query the database and open the appropriate notebook, even if the record is **not in the current folder results**. It does **not** add that record to the folder container or change the current displayed rows. Find's value dropdown holds a **history of prior Find attempts**, not all valid database codes.

When the user clicks OK, BPAL opens the notebook in update or read-only mode according to user authority and the optional **Read Only** checkbox. When Find fails to find the key, BPAL shows an error and leaves the Find dialog open so the value can be corrected. The standard Find function is available in most folders, but is intentionally omitted from a small number of complex folders, including **Contract**; use **Selection Criteria** instead there.

**Vendor and Client** are the two standard folders with a composite code/location primary key. The first location created for a code is designated as primary. An existing secondary location can subsequently be changed to primary, or a new location can be designated primary; BPAL removes the primary designation from the previous location. Entering **code alone** in Find retrieves the **currently primary location**, even if other locations exist. Entering code **and** location retrieves that specific location. To list all locations, use Selection Criteria on the code.

**Q: How do I find a product that isn't displayed in my folder?**  
**A:** Click **Find**, enter its Product Code, and click **OK**. BPAL retrieves it directly by key and opens its notebook. The existing folder results remain unchanged.

**Q: Why does Find show the primary Vendor location rather than the location I want?**  
**A:** If you enter only the Vendor Code, Find selects its designated primary location. Enter Vendor Code and Location to open a specific location, or use **Select** with Vendor Code to display all its locations.

## 9. Open, Read Only, and CDC Manager Record Locks

The folder establishes a user's **read-only** or **update** authority when initialized. Pressing **Open** requires at least one highlighted row; BPAL displays an error if none is selected. For each selected row, it reads the primary key and fetches that record afresh from the database for its notebook.

For read-only authority, the notebook is opened read-only without a CDC Manager update lock. For update authority, the **Open toolbar button** attempts to open in update mode: BPAL first requests a CDC Manager **record-level lock** keyed by the record's primary key. If granted, it fetches the record and opens its notebook in update mode. The lock stays held throughout the update notebook session, even if no changes are made, and is released when that notebook closes.

When another user already holds the update lock, BPAL displays the lock holder's **name, phone, email, lock date/time, and elapsed lock duration**. The user is offered the choice to open the row in read-only mode instead. A failed lock on one of several selected rows affects that row only; other selected rows are processed.

**Right-clicking the OPEN TOOLBAR BUTTON** shows its one extra option: **Open in Read Only Mode**. This retrieves the record without requesting a CDC Manager lock, even when the user has update rights. A right-click on a **folder row** is a different context-menu operation.

Read-only users may view the same record while another user has it open for update. But a read-only notebook is a snapshot of values fetched when opened, **not real-time synchronized**. To see later saved updates, **close and reopen the notebook**. A Refresh inside the open notebook does not exist. User experience indicates simultaneous competing updates and requests for notebook-refresh functionality have been uncommon; notebook refresh is not an established customer requirement.

**Q: BPAL says another user has the record locked. What can I do?**  
**A:** Read the popup to identify the user and how long the lock has been held. You may choose **Read Only** to view the record without changing it, or contact the lock holder to close their update notebook. Do not attempt to bypass the lock.

**Q: Why can't I see a colleague's changes in the record I already have open?**  
**A:** An open read-only notebook does not automatically reload its data. Close it and reopen it to fetch current database values.

## 10. New and Copy

**New** and **Copy** are not shown in folders where the user has read-only authority. **New** opens an empty folder-specific notebook in New mode for entering the record's data. Individual field validation and editing rules are notebook-specific and are not defined by this common reference.

After a successful **Add**, BPAL appends the new row **at the end of the current folder container** and **highlights it**. This deliberate behaviour makes it easy to open and correct the new row, even if it does not meet the folder's current Selection Criteria. No automatic folder Refresh or immediate resort occurs. On the next Refresh the row appears only if it matches the active Selection Criteria and, if present, falls into the normal sort order.

**Copy** requires a highlighted source row and opens a notebook in New mode, prefilled with the source record's data **including its primary key**. The user changes the fields that differ and must change the primary key to a unique value; otherwise BPAL reports the record already exists. A successfully added Copy behaves like New: append and highlight.

**Q: Why did the new product appear at the bottom rather than in sorted order?**  
**A:** BPAL deliberately appends and highlights newly added records so users can find them immediately. The next Refresh applies the normal selection and sorting rules.

## 11. Delete and Referential Integrity

**Delete** is not displayed for read-only folder users. It works directly from highlighted rows in the folder and does not open a notebook. It uses CDC Manager locking for the selected record keys, then asks the user to confirm deletion. Upon a successful physical database deletion, BPAL immediately removes the corresponding row from the folder container without Refresh.

BPAL's database uses **referential integrity constraints**. If another table references a row, the database refuses physical deletion, and BPAL displays an explanatory message. Example: a Vendor referenced by an existing Contract cannot be deleted while the reference remains. Multiple selected rows are handled individually: rows successfully deleted disappear, while a row whose deletion fails stays in the folder and triggers an error message. Locks are released when the operation completes.

**Transactions are an explicit exception**: a Transaction is **never physically deleted**. It may be marked **CANCELLED** or **REJECTED**, but remains in the database. The Transaction folder has no standard Delete toolbar button; designated actions exist inside its update notebook. Detailed Transaction workflows are reserved for later documentation.

**Q: Why can't I delete this vendor?**  
**A:** It may be referenced by a Contract or another related record. BPAL relies on database integrity checks and shows a message when deletion is disallowed. Review the message and existing references rather than attempting to force the delete.

**Q: I deleted three selected rows but only two disappeared.**  
**A:** BPAL processes selected deletions separately. Successful deletions disappear from the folder; any record that cannot be deleted, for example because another table references it, remains with an explanatory message.

## 12. Export to CSV

**Export** writes **all rows currently loaded** in the folder, not just highlighted rows, and **only columns currently visible** through Columns. It preserves left-to-right column order, row sort order and displayed/formatted values exactly as the user sees them (including descriptions and formatted dates). If Refresh was stopped partway through, only that partial set is exported.

The **Export to File** dialog proposes a filename and directory. BPAL remembers the **last export directory per user**. File Type is **Export to CSV (Excel)**. **Include column header** is selected by default each time; uncheck it if you want data-only CSV. Click **Create** to generate the file. BPAL launches the operating system's default program associated with `.csv` files (often Excel) to display it.

**Q: Can I export only certain fields?**  
**A:** Yes. First use **Columns** to show only the fields you want, in the order you want. Then click **Export**. BPAL exports the visible columns and all rows in the folder.

## 13. Folder Split Bar and Scrollbars

A double-line **split bar** divides a folder grid into two sections, each with its **own horizontal scrollbar**. Drag the split bar left or right; the columns on one side remain horizontally stationary while the other side is scrolled. This is useful for retaining identifying information, such as Vendor Code and Name, while examining distant columns.

Users can explicitly **save the split-bar position** via the folder's **Options** menu or the folder's right-click context menu. Separately, BPAL has a **global setting to automatically save split-bar position upon closing folders**. This global auto-save option is **off until explicitly enabled**. Remembered positions are specific to the user and folder, so Vendor and Product can have different split positions.

## 14. Standard Notebook: Navigation, Save and Lookup

### 14.1 Navigation buttons and unsaved changes

Notebook controls **First**, **Previous**, **Next**, **Last** navigate through rows in the underlying folder without closing the notebook. Each navigation changes the highlighted folder row and the notebook's displayed record. At the first row, First and Previous are disabled; analogous boundary controls are disabled at the last row.

If unsaved data edits exist and a user attempts to navigate, BPAL asks: **Data has been changed. Do you want to apply the changes before scrolling?** **Yes** saves then navigates; **No** discards unsaved edits then navigates; **Cancel** remains on the current record. If changes are discarded, navigating back shows original database values, not discarded edits.

### 14.2 OK, Cancel, X, Apply

- **OK**: If data was changed, save the edits to the database and create the corresponding audit; then close the notebook.
- **Cancel** and window **X**: Close the notebook, but if unsaved changes exist, ask whether to save before closing, with Yes/No/Cancel choices. This protects against accidental loss.
- **Apply**: Enabled only when BPAL detects unsaved changes. Saves changes to the database and the audit while **keeping the notebook open** and, for a record opened in update mode, **retaining its CDC Manager lock**. Following a successful Apply, Apply becomes disabled until further edits are made. Previously applied edits are already saved even if later unsaved edits are discarded.

Field-level notebook rules, validations, and the exact behavior of every business-specific tab must be separately documented for the applicable notebook type.

### 14.3 Notebook magnifying glass and Info icon

A **magnifying glass** beside a notebook code field signals a code that references a lookup table. Clicking it opens a **review folder** for the referenced table; example: Product notebook → Product Type code → Product Type folder. This review folder can expose standard folder functions, such as New, Open, Delete, Copy, Columns and Sort, subject to user authority. Users may select the code from the review folder or type a known code directly. If a typed code does not exist in the referenced table, BPAL rejects it with a validation message. An adjacent circled **i** means **Info** and a nearby description may display the referenced code's meaning; detailed Info-button action remains to be confirmed.

**Q: What does the magnifying glass beside Product Type do?**  
**A:** It opens a review folder showing valid Product Types. You can choose one there, or enter a code directly if you know it. An invalid code is rejected because Product Type is validated against its underlying table.

## 15. Mini Containers Inside Notebooks

A **Mini Container** is a folder embedded on a notebook page and associated with the notebook's current parent record. It offers standard folder-style operations as appropriate, and has its own Auto Ref preference. An **update lock on the parent record covers the parent's linked data**, so BPAL does not request additional sub-record locks for its Messages and similar child operations. Adding or editing a child Message saves that child database record immediately; it does not wait for the parent notebook's Apply or OK.

Do not assume that every Mini Container has every main-folder button; use the visible toolbar and authorization. Mini Containers for Messages, Notes and Audit are described below.

## 16. Messages: Record-linked Operational Communications

### 16.1 Message definition

Messages can be linked to Products, Vendors, Carriers, Contracts and other supported record types. Each Message has an effective **From/To date range**, an optional **Sequence** ordering value, **French and English** text, **Active/Inactive** status, and one or more selected **Destinations**. Messages may be added, updated or deleted through the parent notebook's Messages Mini Container according to applicable authority, and saved immediately to the database.

A Product 004 message becomes relevant when a transaction is for Product 004. The same applies to other attached records: a transaction that involves a specific Vendor, Carrier or Contract may activate the associated messages, subject to dates, status and destination. When multiple messages apply, BPAL can show them **together in one message display**, identifying the originating type (e.g., Product, Vendor or Carrier) for each.

### 16.2 Message destinations

The visible Destination controls include: **Terminal (in)**, **Terminal (out)**, **Scale terminal (in)**, **Scale terminal (out)**, **Scale ticket (in)**, **Scale ticket (out)**, **Recycle - receiving**, **Quality analysis**, **Transaction**, and **Purchase Order**. One Message can target multiple destinations. Examples include: a guardhouse terminal advising staff of a driver's safety-equipment issue; a scale-terminal notice about temporary rerouting to a different dumper; an inbound/outbound scale ticket carrying a driver instruction; a laboratory quality warning; or a pricing reminder while administrative staff review a transaction.

### 16.3 Language selection

Each truck-scale installation has a configured **default language** (generally French at Quebec installations, English elsewhere in Canada and the US). Vendor and Carrier data can also specify their preferred language. Before a driver is identified, the initial screen uses the site's language, but drivers can **manually switch** the screen language with a scale-terminal button. When they scan their barcode and BPAL identifies them, the interface may switch to the Vendor/Carrier configured language; users can manually switch it again if desired. The selected language also governs the version of related Messages and scale-ticket text shown or printed. Example: a Quebec vendor arriving at an English-default Ontario location can receive French screens and ticket text.

### 16.4 Example answers

**Q: Can I display a safety warning only for one carrier?**  
**A:** Where Messages are available for that Carrier, create a Message on the carrier record, set its active date range and destinations (for example Terminal In), and enter the required text in French and/or English. BPAL evaluates that Message when transactions involve the carrier.

**Q: Will Product and Vendor messages both appear on a transaction?**  
**A:** Yes, when both apply to the transaction and destination. BPAL presents applicable messages together and identifies whether each comes from Product, Vendor, Carrier, or another linked record.

## 17. Notes and External Attachments

A notebook's Notes Mini Container holds record-specific notes. They can capture warnings, decisions, general comments, or operational context. **One Note per parent record can be marked as the Folder Note.** The user can show the **Folder Note** column in the main folder via Columns, making that note visible without opening each notebook.

Notes may include optional external attachments: photos, scanned agreements, PDF, Word, Excel, emails and other file types. BPAL stores **only the file path and filename**, not the file contents. The file can reside on a shared network location or BPAL server (or elsewhere accessible to the user). Opening the attachment relies on the referenced file remaining available and the user having access to its location. The Notes dialog includes note text, optional attachment name/type, sequence, Folder Note checkbox, and Active/Inactive status.

**Q: I added a photo to a Note, but another user can't open it. Why?**  
**A:** BPAL stores the path to the photo, not a copy. Check whether the file still exists at that path and whether the other user has network/file permissions to access it. A path on one person's local computer might not work for colleagues.

**Q: How do I show a note in the Vendor folder without opening the notebook?**  
**A:** Mark the appropriate Note as the record's **Folder Note**, then use the folder's **Columns** dialog to display the **Folder Note** column.

## 18. Audit and Change History

The **Audit** page displays information such as the record's original **Insert** user/date/time and most recent **Update** user/date/time, plus an embedded Audit Mini Container with past change events. Opening an event displays an **Audit Detail** window with action (for example Update), precise timestamp, user ID/name, table/key, changed column names and **Old Data** versus **New Data**. Several field changes committed together produce **one audit event** containing all changed field entries, rather than one event per field. An Audit Detail window provides Close and Print controls.

Example: a saved update to Product 004 may show French Description, English Description, Tickets In and Moisture in one Audit Detail, with individual old/new values. The audit is a historical record and is not itself a mechanism to undo the edits.

**Pending verification:** The walkthrough did not establish whether changes to child Messages or other Mini Container rows are represented in the parent's Audit tab or a separate audit facility. An apparent gap was noticed, but has **not** been confirmed as missing database audit data. Do not tell users that child Messages are definitely unaudited.

**Q: Who changed a Product description and what was it before?**  
**A:** Open the Product notebook, go to **Audit**, and open the relevant Update event. Audit Detail identifies the user, timestamp, changed field, old value and new value.

## 19. Exceptional Transaction Folder: Confirmed Boundaries Only

Transactions are BPAL's central high-volume data. The Transaction folder's Selection Criteria screen has additional Date/Time, Period, Product Category, Transaction Status, Data Collection and Test controls beyond the standard ten-condition grid. Transactions in the current pay period may be marked **CLOSED**; completed transactions from earlier pay periods may be marked **COMPLETE**. Retrieving COMPLETE historical transactions requires a pay period or date range because transaction tables may hold millions of records. A Transaction is never physically deleted, but can be marked CANCELLED or REJECTED via specific notebook functions.

**Do not give detailed click-by-click instructions for the Transaction-specific period, status, tests or cancellation workflow from this document alone.** Those controls and validation have not yet been comprehensively reviewed. Ask the user for the exact goal and advise consulting the dedicated Transaction training material or BPAL support until added.

## 20. Troubleshooting and Quick Answers

### 20.1 What to ask before troubleshooting

Ask: **Which folder?** **Which button or menu?** **What exact message appeared?** **Read-only or update authority?** **Does the issue involve data already displayed, a new database retrieval, or a notebook?** Avoid asking all five if the user's issue is already clear.

### 20.2 Common symptoms and documented explanations

**New, Copy or Delete button missing** — The folder has been initialized with read-only authority for this user, so those buttons are not shown. Contact an authorized BPAL administrator if update access is required.

**Open says select a row** — Highlight at least one folder row and click Open again.

**Record locked by someone else** — The popup names the lock holder and contact details and offers read-only access. That person's update notebook must close to release the lock.

**A value lookup rejects a typed code** — The code is validated against its linked table. Use the magnifying-glass review folder to inspect permitted entries.

**Numeric selection operator warning** — Choose an operator compatible with the numeric field; text operators such as STARTING WITH are not valid for numeric fields.

**Newly added record appears outside the current sort** — It is intentionally appended and highlighted. Refresh to reapply selection and sorting; it may then disappear if it does not match the criteria.

**A saved Profile no longer sorts** — Its referenced Sort configuration may have been deleted. Inspect the Profile references.

**A CSV does not contain a field** — Only visible folder columns are exported. Use Columns to show it, then export again.

**A CSV contains fewer rows than expected** — Export uses the rows actually loaded into the container. Check Selection Criteria and whether Refresh was interrupted.

**A Note attachment won't open** — BPAL stores a path, not the attachment bytes. Confirm the target location exists and is accessible.

**Audit Detail shows several changed fields** — One committed operation produces one audit event containing the fields changed in that operation.

## 22. Training Examples: User Intent → Correct Answer

**Intent: 'Can I copy another user's filter?'**  
**Answer:** In the folder's Select dialog, choose the other user's ID, pick their saved selection from Save As, then use or save it under your own ID. Saving your changes does not overwrite their version.

**Intent: 'How do I keep the Vendor Code visible while scrolling addresses?'**  
**Answer:** Position the split bar so identifying columns are on the left and scroll the right section. To retain the split position, use the folder Options menu or right-click context menu to save it; alternatively enable the global auto-save split-bar option.

**Intent: 'Can I just click Open to view without locking?'**  
**Answer:** If you have update rights, the Open toolbar button normally requests an update lock. Right-click the **Open toolbar button** and choose **Open in Read Only Mode** to view without a lock.

**Intent: 'I need to make small edits to three adjacent products.'**  
**Answer:** Open a Product notebook and use First/Previous/Next/Last to navigate records in the folder. If you have unsaved edits when navigating, BPAL asks whether to apply them; choose Yes to save, No to discard or Cancel to remain on the current record.

**Intent: 'What's the difference between Apply and OK?'**  
**Answer:** Both save changed notebook data. **Apply** leaves the notebook open and retains its update lock, then disables until another edit. **OK** saves pending edits and closes the notebook.

**Intent: 'How can I print a message on a driver's ticket?'**  
**Answer:** Open the relevant Product/Vendor/Carrier/other supported notebook, use Messages to create the message, enter effective dates and bilingual text, set Active, and select the desired scale-ticket destination, inbound or outbound as needed. BPAL displays/prints the message when the corresponding data participates in an applicable transaction.

**Intent: 'Does the note attachment get copied into BPAL?'**  
**Answer:** No. BPAL keeps the path and filename. Store attachments in a location that intended users can access, and keep the file available there.

**Intent: 'Can I undo a change from the audit log?'**  
**Answer:** This reference confirms that Audit shows old and new values; it does not establish an audit-based Undo or Restore command. If you need to correct a value, use authorized notebook editing and consult support for recovery questions.
